# macOS local music player

Add a compact two-row transparent player in the tracked Codex title bar, below the character overlay and above Codex. Its maximum size is 356 × 44 points. Center it at two-thirds of the window width, clamping its width and position to leave 12-point side margins on narrow layouts. Use a clear native view with no glass/backdrop rectangle or panel shadow; only controls and time labels paint pixels. In narrow windows (under 620 points), offset the player 48 points below the window's top edge to leave window buttons usable. Only the player's bounds receive clicks; the character overlay remains click-through. The player cannot become a key window. A folder chooser, playlist popover or error sheet may receive focus while explicitly open.

Use the system AVAudioPlayer for local audio, playback, seeking, volume and overall level metering; no new runtime dependencies or network access. The first row, left to right: choose folder, playlist, mode, previous, play/pause, next, volume. The second row contains elapsed time, seek slider and total time. Preserve time labels even in compact layouts. Current song is available in tooltips and the playlist; no third row.

The transparent toolbar uses white foreground with fine dark outlines, independent of the companion's own light/dark appearance, because Codex may have a different theme. SF Symbols retain 12-point medium weight (play/pause 14 points) with a 0.7-point dark edge; 9-point medium monospaced time labels have a dark stroke at 3% of font size. Sliders retain a 2-point track and 6-point knob with 1-point dark contours, subdued disabled states and the native accent fill. Hover affects only the individual button. Playlist names and popover colors retain native semantic colors: 12-point regular names with the current song semibold and a 12-point semibold heading. The player retains 8-point horizontal and 3-point vertical content insets, a 26-point control row and a 12-point timeline row. No backdrop, theme-reading permissions or manual theme switch is added. These native component facts do not define a new application-wide brand or design system.

Selecting a folder scans only its directly contained, visible regular audio files, without subfolders. Read and sort filenames off the UI thread, then automatically play the first playable song in the sorted list, including when shuffle mode is already selected; shuffle governs subsequent advancement. Canceling, an empty folder or an unreadable/unplayable replacement preserves the current playlist and playback. Skip unplayable candidates during automatic advancement; report an error if no candidate can play. Clicking an unavailable song reports the error without stopping the old song. No saved folder paths or playback position, playlists from network sources, metadata-tag sorting, or system-audio capture.

Sort by filename: case/width-insensitive Latin A–Z; Han-leading names by the system Mandarin-to-Latin transform (diacritics ignored); kana-leading names by Japanese gojuon collation (hiragana/katakana unified); other names last. Mixed filenames use the first character to choose the group. Within groups use natural numeric comparison and deterministic filename ties. Default mode loops the entire sorted playlist, including automatic advancement at EOF. Random mode chooses a random next song, excluding the current song when another playable candidate exists. It repeats the sole playable song when all other candidates are unplayable. Previous follows actual playback history and is disabled when history is empty. Mode changes preserve current time and playback. Selecting a different song starts it immediately; selecting the current paused song resumes it without resetting time.

The playlist opens below its button in a 320-point-wide native popover. Its scroll viewport holds exactly five complete 32-point rows (fewer for a smaller playlist), scrolls through the entire list, marks the current track and switches on a single click. Use a plain native table with no automatic row inset; five rows occupy a 160-point viewport and a 204-point content height. Keep the 18-point heading frame, 10-point top padding and content size stable after playback or language refresh. A speaker marks the playing current song and a checkmark marks it while paused. Close the popover after successful selection and when the player hides. Empty playlist/play/previous/next/seek controls are disabled as appropriate. Folder loading has a visible busy state and prevents duplicate scans. Native errors remain recoverable.

Music continues when another app is foreground or the overlay is hidden. Hiding only the music controls closes the playlist but preserves playback and audio-level delivery for the visible character. Stop metering when the character overlay is hidden; stop control refreshes while its window is hidden, and stop audio on exit. Start at 50% player volume. Mute produces no music-driven motion. Retain English, Chinese and Japanese UI and live language switching. The sun menu provides a Hide/Show music controls action; see macos-click-ripple.md for the companion ripple toggle.

Pass a bounded overall strength (0–1) into the shared renderer, only while visible. Smooth with a ~0.22-second attack and ~0.65-second release; preserve the existing slow hair phases and delayed tips. Cap additional gain separately for each character. Additional motion is limited to conservative back-hair regions, excluding the face/ear and clothing, and keeps anchored roots. Pause, mute, end and error decay to the original gentle motion. Reduce Motion stays static; hidden animation stops. Windows supplies no music input and retains its current behavior.
